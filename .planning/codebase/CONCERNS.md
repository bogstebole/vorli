## Security

### API Key in UserDefaults
**Severity: High**
- The Anthropic API key (`sk-ant-...`) is stored in plain `UserDefaults`
- Location: `Receipt Tracker/VorliService.swift:76`, `Receipt Tracker/SettingsSheet.swift:17`
- **Risk:** UserDefaults is accessible to other apps on jailbroken devices and is not encrypted
- **Fix:** Migrate to iOS Keychain (`SecItemAdd` / `KeychainAccess` package)

## Architecture Concerns

### ReceiptService Instantiated Ad-Hoc
- `ReceiptService` is created inline per operation in ContentView rather than injected as a dependency
- Makes testing harder and can cause context threading issues with SwiftData

### No Error Boundary in ContentView
- Errors from `ReceiptService` async operations are not systematically surfaced to the user
- Parser errors (`ReceiptParser.ParserError`) are well-typed but may be silently swallowed upstream

## Testing Gap

- **Zero automated tests** despite `ENABLE_TESTABILITY = YES` in build settings
- Manual testing via debug views only: `DebugParserView`, `ReceiptHTMLDebugView`, `OCRTestView`
- Highest-risk untested code: `ReceiptParser` (network + HTML parsing), `ReceiptOCRParser` (Vision OCR), `VorliContextBuilder` (prompt assembly)

## Performance

### Potential SwiftData Over-fetch
- `VorliContextBuilder` serialises receipts to JSON for AI context — no limit on receipt count
- As the receipt database grows, context assembly could become slow and exceed Anthropic token limits
