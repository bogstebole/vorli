In VorliChatViewModel.swift, make the following targeted changes:

1. Add a private stored property for the optional budget immediately after `private let allReceipts: [Receipt]`:
```swift
private let budget: Budget?
```

2. Extend the `init` to accept `budget: Budget? = nil` (default nil preserves any future call sites not passing budget):
```swift
init(allReceipts: [Receipt], budget: Budget? = nil) {
    self.allReceipts = allReceipts
    self.budget = budget
}
```

3. In `buildContext(for:)`, update all three call sites of `VorliContextBuilder.build()` to pass `budget:` and `userProfile:`. The `userProfile` is already loaded via `VorliUserProfile.load()` in `send()` — load it once in `buildContext(for:)` instead, or pass it as a parameter. The cleanest approach: load the profile inside `buildContext(for:)` and pass it to every `VorliContextBuilder.build()` call:

```swift
private func buildContext(for requestType: String) -> String {
    let profile = VorliUserProfile.load()
    switch requestType {
    case "REPORT_MONTH":
        let current = VorliContextBuilder.receiptsForCurrentMonth(from: allReceipts)
        let previous = VorliContextBuilder.receiptsForPreviousMonth(from: allReceipts)
        return VorliContextBuilder.build(currentReceipts: current, previousReceipts: previous, requestType: "REPORT", budget: budget, userProfile: profile)

    case "REPORT_WEEK":
        let current = VorliContextBuilder.receiptsForCurrentWeek(from: allReceipts)
        let previous = VorliContextBuilder.receiptsForPreviousWeek(from: allReceipts)
        return VorliContextBuilder.build(currentReceipts: current, previousReceipts: previous, requestType: "REPORT", budget: budget, userProfile: profile)

    default:
        let cutoff = Calendar.current.date(byAdding: .month, value: -6, to: Date()) ?? Date()
        let recent = allReceipts.filter { $0.timestamp >= cutoff }
        return VorliContextBuilder.build(currentReceipts: recent, requestType: "PRETRAGA", budget: budget, userProfile: profile)
    }
}
```

Note: Remove the `VorliUserProfile.load()` call from `send()` since it now happens in `buildContext()`. Pass the loaded profile to `service.sendMessage(userProfile:)` — to do this, either load profile in `send()` as before (keeping both calls, one for context and one for service), or refactor slightly. The safest minimal change: keep `VorliUserProfile.load()` in `send()` for the `service.sendMessage` call, and add a second `VorliUserProfile.load()` inside `buildContext()`. Loading from UserDefaults twice per message is negligible overhead.

Do NOT change anything else in the file — QuickPrompts, message state, streaming logic, or error handling are untouched.
